`nestjs-drizzle-crud` is a NestJS Drizzle library: you extend one base class per table and get a
typed CRUD service on top of Drizzle ORM. You configure the connection once, bind each service to
its Drizzle table, and every service can find, list, filter, paginate, create, update, soft delete
and bulk write rows on PostgreSQL or MySQL. It does not hide Drizzle: your schema stays yours.

<Callout title="Who this is for, and what you need">
  NestJS developers who use Drizzle ORM, or want to, and are tired of writing the same `findAll`,
  `create` and `update` code in every service. You need Node 20 or later, `@nestjs/common` and
  `@nestjs/core` 10 or later, `drizzle-orm` from 0.28.0 up to (not including) 1.0.0, and
  `reflect-metadata` 0.1.13 or 0.2. Add `postgres` 3 if you want the module to open the
  PostgreSQL connection for you.
</Callout>

## What does it do?

One empty service class gives you the whole read and write surface, and configuration turns on
the rest:

- **Reads.** `find`, `findOne`, `findAll` with a `{ data, total, page, limit }` envelope,
  `count` and `exists`. See [CRUD operations](/docs/crud-operations).
- **Filtering.** Column operators (`gte`, `in`, `between`, `iContains` and more), `and`, `or`
  and `not` groups, and filters on related tables. See [Filtering](/docs/filtering) and
  [Relation filters](/docs/relation-filters).
- **Pagination.** Offset pages with a capped limit, multi-column sorts, and keyset pagination
  through `findByCursor`. See [Pagination and sorting](/docs/pagination-sorting) and
  [Cursor pagination](/docs/cursor-pagination).
- **Relations.** Belongs-to, has-many and many-to-many, eager loaded with one batched query per
  relation instead of one per row. See [Relations](/docs/relations).
- **Writes.** `create`, `update`, `upsert`, soft delete, restore, and mass writes that run in one
  transaction. See [Upsert](/docs/upsert), [Bulk operations](/docs/bulk-operations) and
  [Soft delete](/docs/soft-delete).
- **Safety.** Column allowlists, tenant scopes, optimistic locking, and exceptions that map to
  404, 409 and 400 without a custom filter. See [Allowlists](/docs/allowlists),
  [Multi-tenancy](/docs/multi-tenancy) and [Errors](/docs/errors).
- **Wiring.** A generated controller, OpenAPI decorators, test helpers and an MCP server for
  coding agents. See [Controller factory](/docs/controller-factory) and
  [AI agents](/docs/ai-agents).

## What does a service look like?

A service is an empty class that names its row, DTO and filter types. `forFeature` binds it to a
table and builds it for you, so there is no constructor and no `@Injectable()`.

```ts title="users/users.service.ts"
import { type CrudFilter, SqlBaseCrudService } from "nestjs-drizzle-crud";
import type { users } from "../db/schema";
import type { CreateUserDto, UpdateUserDto } from "./users.dto";

export type User = typeof users.$inferSelect;

export class UsersService extends SqlBaseCrudService<
  User,
  CreateUserDto,
  UpdateUserDto,
  CrudFilter
> {}
```

```ts accent=nest title="users/users.module.ts"
import { Module } from "@nestjs/common";
import { DrizzleCrudModule } from "nestjs-drizzle-crud";
import { users } from "../db/schema";
import { UsersController } from "./users.controller";
import { UsersService } from "./users.service";

@Module({
  imports: [
    DrizzleCrudModule.forFeature([{ service: UsersService, table: users }]),
  ],
  controllers: [UsersController],
})
export class UsersModule {}
```

`UsersService` now has every method in [CRUD operations](/docs/crud-operations), typed against
`User`. The [quick start](/docs/quick-start) builds the rest of the app around it.

## When is it the wrong tool?

- **Most of your endpoints are reports.** Window functions, CTEs and hand-tuned joins read better
  as plain Drizzle. You can still add those as extra methods on the same service.
- **Your writes are workflows.** Multi-step domain operations belong in your own service code.
  Use the package for the plain entities around them.
- **You need SQLite or another dialect.** The `dialect` setting accepts `"postgresql"` and
  `"mysql"` only.

## Common questions

<Accordions>
  <Accordion title="Does nestjs-drizzle-crud replace Drizzle ORM?">
    No. It builds Drizzle queries from your own Drizzle tables. You keep your schema and migrations, and you can inject `DRIZZLE_DB` to run any Drizzle query yourself.
  </Accordion>
  <Accordion title="Which databases does it support?">
    PostgreSQL and MySQL. Full-text search and building the connection from a `connectionString` are PostgreSQL only; on MySQL you pass a Drizzle instance you built yourself.
  </Accordion>
  <Accordion title="Do I have to write controllers?">
    No. `createCrudController` generates the list, get, create, update, delete and bulk routes for a service. You can also write a normal NestJS controller and call the service methods yourself.
  </Accordion>
  <Accordion title="Does loading relations cause N+1 queries?">
    No. A belongs-to relation is joined into the main query, and has-many and many-to-many relations load with one batched query per relation for the whole result, whatever the row count.
  </Accordion>
  <Accordion title="Is it free to use in a commercial project?">
    Yes. The package is MIT licensed and has no runtime dependencies of its own.
  </Accordion>
</Accordions>
