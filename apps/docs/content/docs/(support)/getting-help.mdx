To get help with nestjs-drizzle-crud, ask usage questions in GitHub Discussions, report a bug you can reproduce as a GitHub issue, and report a security vulnerability privately through a GitHub security advisory. A report that includes the package version, the table definition, the entity config and the exact call gets answered fastest.

<Callout type="warn" title="Never report a vulnerability in public">
  Do not put a security problem in an issue, a discussion or a pull request. Use the private
  advisory form described under the security question below, which only the maintainers can see.
</Callout>

## Where do I ask?

Pick the channel by what you need; each one is watched.

| You want to | Go to |
| --- | --- |
| Ask how to do something | [GitHub Discussions](https://github.com/avytrix/nestjs-drizzle-crud/discussions) |
| Report a bug you can reproduce | <Ext to="issues">GitHub issues</Ext>, bug report template |
| Request a feature | <Ext to="issues">GitHub issues</Ext>, feature request template |
| Report a security vulnerability | [A private security advisory](https://github.com/avytrix/nestjs-drizzle-crud/security/advisories/new) |
| Contribute code | [CONTRIBUTING.md](https://github.com/avytrix/nestjs-drizzle-crud/blob/main/CONTRIBUTING.md) |
| Fund the work | [Sponsor nestjs-drizzle-crud](/docs/sponsor) |

Blank issues are turned off, so every issue starts from the bug report or feature request template.

## What should a bug report include?

A report with a reproduction usually gets fixed in one round trip. The bug report template asks for most of this; fill in all of it:

1. The `nestjs-drizzle-crud` version, the dialect, and your Node, NestJS and Drizzle versions.
2. The Drizzle table definition for the entity, trimmed to the relevant columns.
3. The `forRoot` and `forFeature` config for that entity.
4. The call you made and what came back, including the exception class and HTTP status.
5. The SQL, if you have it. Drizzle logging (`drizzle(client, { logger: true })`) prints the statement the service built.
6. The stack trace, if there is one.

Search the existing issues first; the template asks you to confirm the bug is not a duplicate.

## How do I report a security vulnerability?

Report it privately through [GitHub's security advisory form](https://github.com/avytrix/nestjs-drizzle-crud/security/advisories/new), as the [security policy](https://github.com/avytrix/nestjs-drizzle-crud/blob/main/SECURITY.md) says. Include:

- What the vulnerability is and what an attacker could do with it.
- Steps to reproduce, ideally a minimal proof of concept.
- The affected version or versions.

The maintainers acknowledge reports within 72 hours, work with you on a fix and agree a disclosure date. Reporters are credited in the advisory unless they prefer otherwise.

| Question | Answer |
| --- | --- |
| What is in scope? | The published npm package, `packages/nestjs-drizzle-crud`. |
| What is out of scope? | `apps/api` and `apps/docs`, the private example app and this docs site. Report problems there as normal issues. |
| Which versions get security fixes? | 3.x. Versions before 3.0 do not. |

## Common questions

<Accordions>
  <Accordion title="Why does findAll return an object instead of an array?">
    `findAll` returns `{ data, total, page, limit }` because every list is paginated. `total` comes from a count query with the same filters and search, so it stays correct as you page.
  </Accordion>
  <Accordion title="Why is my like filter not matching anything?">
    `like` and `ilike` use the wildcards you supply, so `{ name: { ilike: "jo" } }` only matches `jo`. Write `{ name: { ilike: "jo%" } }`, or use `startsWith`, which adds and escapes the wildcard for you.
  </Accordion>
  <Accordion title="Why does my service fail at startup with a missing column?">
    Soft delete and timestamps are on by default and expect `deleted_at`, `created_at` and `updated_at`. Turn them off with `defaults: { softDelete: false, timestamps: false }`, or point them at your column keys.
  </Accordion>
  <Accordion title="Do I need to inject the database into my service?">
    No. `forFeature` builds the service and hands it the config, Drizzle instance included. Adding `@Injectable()` or an `@Inject(DRIZZLE_DB)` constructor breaks that registration.
  </Accordion>
  <Accordion title="Does it work with MySQL?">
    Yes. Pass a `mysql://` connection string or your own Drizzle MySQL instance as `db`, and the package reads written rows back because MySQL has no `RETURNING`. Full-text search and the array and JSON operators are PostgreSQL only.
  </Accordion>
</Accordions>
