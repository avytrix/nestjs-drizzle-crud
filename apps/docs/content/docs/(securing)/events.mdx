---
title: Global hooks and write events
description: "Turn on hooks.enableGlobalHooks and subscribe to CrudEventBus for before and after events on every write, bulk and upsert included. For audit trails and cache busting."
---

With `hooks.enableGlobalHooks: true`, every service raises a before event and an after event for each write on a module-level `CrudEventBus`: create, update, upsert, soft delete, restore, delete, attach, detach and sync, with each mass write raising one pair for the whole batch. Subscribe once and you see every entity, which is what an audit trail or a cache needs.

```ts accent=nest title="app.module.ts"
DrizzleCrudModule.forRoot({
  dialect: 'postgresql',
  connectionString: process.env.DATABASE_URL,
  hooks: {
    enableGlobalHooks: true,
    subscribers: [
      { afterWrite: (e) => console.log(e.entity, e.operation, e.ids) },
    ],
  },
});
```

## How do I subscribe from a provider?

Inject `CrudEventBus` and call `subscribe`. It returns a function that unsubscribes:

```ts accent=nest title="audit.service.ts"
import { Injectable, type OnModuleInit } from '@nestjs/common';
import { CrudEventBus } from 'nestjs-drizzle-crud';

@Injectable()
export class AuditService implements OnModuleInit {
  constructor(private readonly bus: CrudEventBus) {}

  onModuleInit() {
    this.bus.subscribe({
      afterWrite: async (event) => {
        const db = event.transaction ?? this.db;
        await db.insert(auditLog).values({
          entity: event.entity,
          operation: event.operation,
          ids: event.ids.map(String),
        });
      },
    });
  }
}
```

Writing through `event.transaction` puts the audit row in the same transaction as the write, so both commit or both roll back. In `forRootAsync` the factory can return `hooks.subscribers` built from injected services.

## What does a subscriber look like?

Every method is optional:

| Method | Called for |
| --- | --- |
| `beforeWrite`, `afterWrite` | every operation |
| `beforeCreate`, `afterCreate` | `create`, `massCreate` |
| `beforeUpdate`, `afterUpdate` | `update`, `massUpdate` |
| `beforeUpsert`, `afterUpsert` | `upsert`, `massUpsert` |
| `beforeSoftDelete`, `afterSoftDelete` | `softDelete`, `massSoftDelete` |
| `beforeRestore`, `afterRestore` | `restore`, `massRestore` |
| `beforeDelete`, `afterDelete` | `delete`, `forceDelete`, `massDelete`, `massForceDelete` |
| `beforeAttach` / `afterAttach`, `beforeDetach` / `afterDetach`, `beforeSync` / `afterSync` | the many-to-many link methods |

`entities: ['posts', 'authors']` limits a subscriber to those table names. Listeners run in the order they subscribed and are awaited.

## What is in an event?

```ts
interface CrudEvent<T = any> {
  entity: string;            // the table name
  operation: 'create' | 'update' | 'upsert' | 'softDelete' | 'restore'
    | 'delete' | 'attach' | 'detach' | 'sync';
  phase: 'before' | 'after';
  bulk: boolean;             // true for the mass methods
  ids: unknown[];            // primary keys; empty before a create or upsert
  input?: unknown;           // the DTO, the array of DTOs, or the related ids
  rows: T[];                 // after: the rows as stored; empty for deletes
  transaction?: unknown;     // the transaction the write runs in, if any
  context?: Record<string, unknown>; // options.context or CrudContext
}
```

## How do bulk writes raise events?

Once per call, with `bulk: true`, all the ids in `ids` and every written row in `rows`. A `massUpdate` of 500 rows is two events, not a thousand. With `bulkMode: 'perItem'` each item goes through the single-row method, so you get one pair of events per item with `bulk: false`.

## Can a listener stop a write?

A before listener that throws stops it: nothing is written and the caller gets the error (a Nest `HttpException` keeps its status). An after listener that throws inside a transaction rolls the write back. Every mass write runs in a transaction; a single write only does when you pass one in `options.transaction`.

## How do I bust a cache?

```ts
bus.subscribe({
  entities: ['products'],
  afterWrite: (e) => {
    for (const id of e.ids) cache.delete(`product:${id}`);
    cache.delete('products:list');
  },
});
```

## How do events relate to the per-service hooks?

They are separate and both run. The protected hooks on a service (`beforeCreate`, `afterUpdate`, ...) keep working as before and still follow `options.hooks.skipBefore` / `skipAfter`. Events follow `options.skipEvents` instead, so skipping a hook never silently skips the audit trail. See [Hooks and validation](/docs/hooks-validation).

With `enableGlobalHooks` off (the default) no events fire, and the module warns at startup if `hooks.subscribers` is set anyway.

## How do I use events without the module?

Pass a bus in the config when you build a service by hand, as in tests:

```ts
const bus = new CrudEventBus();
bus.subscribe({ afterWrite: (e) => seen.push(e) });
const posts = new PostsService({ ...config, events: bus });
```
