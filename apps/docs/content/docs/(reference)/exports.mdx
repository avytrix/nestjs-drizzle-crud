Every export below is available from the package root: `import { ... } from 'nestjs-drizzle-crud'`.

## Core

| Export | Kind | Description |
| --- | --- | --- |
| `SqlBaseCrudService` | class | The base class your services extend. See [API reference](/docs/api). |
| `parseCrudQuery` | function | `parseCrudQuery(query, table, options?)` turns an HTTP query object into filters, pagination and options. Since 3.4.0. See [Parse query strings](/docs/query-parsing). |
| `createCrudController` | function | `createCrudController(Service, options?)` returns a controller class with list, get, create, update, delete, soft delete, restore, trash and bulk routes. Since 3.5.0. See [CRUD controller factory](/docs/controller-factory). |
| `CrudContext` | object | `run(context, fn)`, `current()` and `middleware(resolve)`: the per-request context a `scope` reads, in `AsyncLocalStorage`. Since 3.5.0. See [Multi-tenancy](/docs/multi-tenancy). |
| `CrudEventBus` | class | The module-level event bus behind `hooks.enableGlobalHooks`. Inject it and call `subscribe`. Since 3.5.0. See [Global hooks and write events](/docs/events). |

## OpenAPI

Both need the optional peer `@nestjs/swagger`, loaded only when a decorator runs. Since 3.5.0. See [OpenAPI docs for list queries](/docs/openapi).

| Export | Kind | Description |
| --- | --- | --- |
| `ApiCrudQuery` | decorator | Documents every list query parameter and each filterable column. |
| `ApiCrudList` | decorator | `ApiCrudQuery` plus the 200 page envelope with the row schema. |
| `ApiCrudSource`, `ApiCrudQueryOptions` | types | The decorators' source (`{ table, ...allowlists }` or a `@CrudService` class) and options (`{ cursor?, trash? }`). |

## Exceptions

All exceptions extend `@nestjs/common`'s `HttpException`, so Nest's default exception filter maps them to HTTP status codes automatically. They are real classes. Use `instanceof` checks in your exception filters. See [Errors](/docs/errors) for the per-method reference.

| Export | HTTP | Description |
| --- | --- | --- |
| `EntityNotFoundException` | 404 | Thrown by `update`, `restore`, `massUpdate`, `massRestore` when the row doesn't exist. |
| `DuplicateEntityException` | 409 | Thrown by `create` / `update` when a unique constraint is violated (Postgres SQLSTATE `23505`). |
| `ForeignKeyViolationException` | 400 | Thrown by `create` / `update` when a supplied foreign key references no existing row (`23503`). Names the offending column. |
| `StaleVersionException` | 409 | Optimistic locking: a write named a version the row is no longer at. Since 3.5.0. See [Optimistic locking](/docs/optimistic-locking). |
| `MissingScopeException` | 403 | A scoped entity was used without the context value its scope needs. Since 3.5.0. See [Multi-tenancy](/docs/multi-tenancy). |
| `EntityInUseException` | 409 | Thrown by `delete` when other rows still reference this one (`23503`, `ON DELETE RESTRICT` or `NO ACTION`). |
| `ValidationFailedException` | 400 | Throw this from your `validateCreate` / `validateUpdate` hooks to reject bad input. |
| `BulkOperationException` | 400 | Thrown by any bulk method when the transaction rolls back. The response body lists each failed item as `{ index \| id, status, message }`; `errors` keeps the original errors. |
| `DatabaseConnectionException` | 500 | **Deprecated.** Nothing in the package throws it. Removed in the next major version. |
| `TransactionException` | 500 | **Deprecated.** Nothing in the package throws it; a failed transaction rejects with its own error. Removed in the next major version. |

## Re-exported Drizzle helpers

For convenience, the package re-exports the Drizzle helpers most commonly used in `mapCreateDtoToEntity`, custom methods, and filter construction:

```ts
import {
  and,
  asc,
  between,
  desc,
  eq,
  gt,
  gte,
  ilike,
  inArray,
  isNotNull,
  isNull,
  like,
  lt,
  lte,
  ne,
  not,
  notInArray,
  or,
  sql,
} from 'nestjs-drizzle-crud';
```

All of these are pass-throughs to `drizzle-orm`. The package doesn't wrap or extend them.

## What's **not** exported

The following are internal to the package and should not be imported directly:

- `DrizzleCrudModule`'s internal `connectionProviders` / `buildEntityConfig` / `normalizeConfig` helpers.
- The internal `DRIZZLE_RAW_CONFIG` token.

If you find yourself reaching for these, open a feature request. The public API may need a hook.
