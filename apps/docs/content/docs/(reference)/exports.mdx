nestjs-drizzle-crud exports 98 names from its package root: 79 of its own (classes, functions, decorators, DI tokens, exceptions, test helpers and types) and 19 Drizzle helpers re-exported unchanged. Import all of them with `import { ... } from "@avytrix/nestjs-drizzle-crud"`. Anything not listed here is internal and can change in any release.

<Callout title="The root is the only public entry point">
  `src/index.ts` is the public surface. Removing or renaming anything on this page is a major
  version, so code that imports only from the root survives every minor and patch upgrade.
</Callout>

## Core

| Export | Kind | Description |
| --- | --- | --- |
| `SqlBaseCrudService` | abstract class | The base class your services extend. See [SqlBaseCrudService API reference](/docs/api). |
| `DrizzleCrudModule` | class | The Nest module, with `forRoot`, `forRootAsync` and `forFeature`. |
| `CrudService` | decorator | `@CrudService(config)` stores per-entity config on a service class. The `forFeature` `config` wins over it. |
| `parseCrudQuery` | function | `parseCrudQuery(query, table, options?)` turns an HTTP query object into filters, pagination and options. Since 3.4.0. See [NestJS query string filters for Drizzle](/docs/query-parsing). |
| `createCrudController` | function | `createCrudController(Service, options?)` returns a controller class with list, trash, get, create, update, delete, soft delete, restore and bulk routes. Since 3.5.0. See [NestJS CRUD controller generator](/docs/controller-factory). |
| `CrudContext` | object | `run(context, fn)`, `current()` and `middleware(resolve)`: the per-request context a `scope` reads, kept in `AsyncLocalStorage`. Since 3.5.0. See [Multi-tenancy](/docs/multi-tenancy). |
| `CrudEventBus` | class | The module-level event bus behind `hooks.enableGlobalHooks`. `forRoot` and `forRootAsync` provide it globally; inject it and call `subscribe`. Since 3.5.0. See [Events](/docs/events). |

## Exceptions

Every exception extends a Nest `HttpException` subclass, so the default exception filter maps it to its status without a custom filter, and you can match it with `instanceof`. See [Error handling](/docs/errors).

| Export | HTTP | When |
| --- | --- | --- |
| `EntityNotFoundException` | 404 | `update`, `softDelete`, `restore` or `delete` on a missing row, and per id in a mass write. |
| `DuplicateEntityException` | 409 | A unique constraint is violated (Postgres `23505`). |
| `StaleVersionException` | 409 | Optimistic locking: a write named a version the row is no longer at. Since 3.5.0. |
| `EntityInUseException` | 409 | `delete` while other rows still reference the row (`23503`). |
| `MissingScopeException` | 403 | A scoped entity was used without the context value its scope needs. Since 3.5.0. |
| `ForeignKeyViolationException` | 400 | `create` or `update` references a parent row that does not exist (`23503`). Names the column. |
| `ValidationFailedException` | 400 | Bad input: a value the column cannot take, an update with nothing to set, a column outside `writableColumns`. Throw it from your validation hooks too. |
| `BulkOperationException` | 400 | A bulk method rolled back. The body lists each failed item as `{ index \| id, status, message }`; the `errors` property keeps the original errors. |
| `DatabaseConnectionException` | 500 | **Deprecated.** Nothing throws it. Removed in the next major version. |
| `TransactionException` | 500 | The driver cannot run the transaction a call needs (Cloudflare D1, synchronous SQLite drivers). Thrown since 3.7.0; it was deprecated before. A failed transaction still rejects with its own error. |

## Re-exported Drizzle helpers

These are pass-throughs from `drizzle-orm`, re-exported so a custom method or `mapCreateDtoToEntity` override needs one import. The package does not wrap or change them.

```ts accent=drizzle title="users.service.ts"
import {
  and,
  asc,
  between,
  desc,
  eq,
  gt,
  gte,
  ilike,
  inArray,
  isNotNull,
  isNull,
  like,
  lt,
  lte,
  ne,
  not,
  notInArray,
  or,
  sql,
} from "@avytrix/nestjs-drizzle-crud";
```

## What is not exported?

The module's internal helpers (`normalizeConfig`, `buildEntityConfig`, `connectionProviders`), the `DRIZZLE_RAW_CONFIG` token, and the service's private methods are not part of the API. If you need one of them, open an issue on <Ext to="issues">the issue tracker</Ext>: the public API may need a hook.

## Common questions

<Accordions>
  <Accordion title="How many exports does nestjs-drizzle-crud have?">
    98: 79 of its own and 19 Drizzle helpers. Of its own, 25 are runtime values (classes, functions, decorators, tokens, exceptions and test helpers) and 54 are types.
  </Accordion>
  <Accordion title="Is the MCP server an export?">
    No. `nestjs-drizzle-crud-mcp` is a command-line binary in the package, not an import. Run it with `npx -p @avytrix/nestjs-drizzle-crud nestjs-drizzle-crud-mcp`.
  </Accordion>
  <Accordion title="Can I import from a deep path such as dist/core?">
    Deep paths are internal and can change in any release. Import from the package root only.
  </Accordion>
  <Accordion title="Why are the Drizzle helpers re-exported?">
    So code that extends a service can build conditions with `eq`, `and` or `sql` from the same import. They are the `drizzle-orm` functions themselves, unchanged.
  </Accordion>
</Accordions>
