nestjs-drizzle-crud is configured through two types: `DrizzleCrudConfig`, the project config you pass to `forRoot` or `forRootAsync`, and `SqlCrudConfig`, the merged per-entity config each service runs on. The module builds the second from the first, then layers `@CrudService` metadata and the `forFeature` config on top, so an entity only names the settings it changes.

<Callout title="Column settings take the table key">
  `softDelete.column`, `timestamps.createdAt`, `timestamps.updatedAt`, `versionColumn` and the keys
  of a fixed `scope` name the key in your Drizzle table object (`deletedAt` for
  `deletedAt: timestamp("deleted_at")`), not the SQL name. A key the table lacks throws when the
  service is built, with the key to use.
</Callout>

## `DrizzleCrudConfig`

The input to `DrizzleCrudModule.forRoot(config)`, and what the `forRootAsync` factory returns. It holds the connection and the project defaults.

Provide one of `db` or `connectionString`; with neither, startup fails. A `connectionString` with `dialect: "sqlite"` also fails, because only PostgreSQL and MySQL connections are built for you.

```ts title="drizzle-crud-config.interface.ts"
interface DrizzleConnectionOptions {
  poolSize?: number;    // postgres-js max, mysql2 connectionLimit
  idleTimeout?: number; // seconds: postgres-js idle_timeout, mysql2 idleTimeout x 1000
  ssl?: boolean | "require" | "allow" | "prefer" | "verify-full" | Record<string, unknown>;
}

interface DrizzleCrudOptionsFactory {
  createDrizzleCrudOptions(): DrizzleCrudConfig | Promise<DrizzleCrudConfig>;
}

interface DrizzleCrudAsyncOptions {
  imports?: any[];
  inject?: any[];
  useFactory?: (...args: any[]) => DrizzleCrudConfig | Promise<DrizzleCrudConfig>;
  useClass?: Type<DrizzleCrudOptionsFactory>;
  useExisting?: Type<DrizzleCrudOptionsFactory>;
}
``` See [NestJS Drizzle module forRoot options](/docs/for-root) and [Drizzle forRootAsync with ConfigService](/docs/for-root-async).

`sql.jsonSupport`, `sql.enableFullTextSearch` and `primaryKeyType` are deprecated and have no effect. They still compile so existing configs keep working, and they will be removed in the next major version. `hooks.enableGlobalHooks` was deprecated as a no-op in 3.3.1 and works again since 3.5.0: it turns on [write events](/docs/events).

## How is `SqlCrudConfig` built?

Each entity's config is the project defaults with three layers on top, each overriding the one before:

| Layer | Source |
| --- | --- |
| 1 | `forRoot` / `forRootAsync` defaults, after the module fills in its own |
| 2 | `@CrudService(config)` decorator metadata on the service class |
| 3 | The `config` object in `forFeature` |
| 4 | `db` and `table`, set by `forFeature` |

`softDelete`, `timestamps`, `pagination` and `sql` merge one level deep at every layer, so `pagination: { defaultLimit: 5 }` keeps the project `maxLimit`. Every other key, the allowlist arrays included, replaces the value from the layer before. `timestamps: undefined` turns timestamps off for that entity.

## `CrudFeature` and `CrudFeatureConfig`

`forFeature` takes an array of `CrudFeature`, one per entity.

```ts title="drizzle-crud-config.interface.ts"
interface CrudFeature {
  service: new (...args: any[]) => any; // your SqlBaseCrudService subclass
  table: any;                           // the Drizzle table
  config?: CrudFeatureConfig;           // per-entity overrides
}

type CrudFeatureConfig = Partial<
  Omit<SqlCrudConfig, "softDelete" | "timestamps" | "pagination" | "sql">
> & {
  softDelete?: Partial<NonNullable<SqlCrudConfig["softDelete"]>>;
  timestamps?: Partial<NonNullable<SqlCrudConfig["timestamps"]>>;
  pagination?: Partial<NonNullable<SqlCrudConfig["pagination"]>>;
  sql?: Partial<NonNullable<SqlCrudConfig["sql"]>>;
};
```

Every key of `CrudFeatureConfig` is optional. Before 3.3.1, `config` was typed `Record<string, any>`, so a typo or a half-filled `pagination` compiled. See [forFeature](/docs/for-feature).

```ts accent=nest title="users.module.ts"
DrizzleCrudModule.forFeature([
  {
    service: UsersService,
    table: users,
    config: {
      softDelete: { column: "deletedAt" },
      pagination: { defaultLimit: 50 },
      filterableColumns: ["name", "status", "state.name"],
    },
  },
]);
```

## `RelationNode` and `SelectTree`

The resolved eager-loading plan and the parsed `options.select`. Both are exported for subclasses that override the loader; normal use never touches them.

interface RelationNode {
  name: string;
  config: RelationConfig;
  children: RelationNode[];
  joined?: boolean; // folded into the main query as a LEFT JOIN
}

interface SelectTree {
  base: string[];
  relations: Record<string, SelectTree>;
}
```

## `SqlOperationOptions` and `SqlSearchOptions`

`SqlOperationOptions` is the last argument of every method; its keys are listed on the [API reference](/docs/api#sqloperationoptions). Its `search` key is a `SqlSearchOptions`:

```ts title="sql-crud-config.interface.ts"
type SqlSearchMode = "ilike" | "fullText";
type FullTextQueryMode = "plain" | "websearch";

interface FullTextOptions {
  language?: string;             // default "english"
  queryMode?: FullTextQueryMode; // default "plain"
}

interface SqlSearchOptions extends FullTextOptions {
  term: string;
  columns: string[];
  mode?: SqlSearchMode; // default "ilike"
}

// The options of fullTextSearch()
interface FullTextSearchOptions<FilterDto = any>
  extends SqlOperationOptions, FullTextOptions {
  filters?: FilterDto;
}
```

`ilike` matches each column with an escaped contains pattern and joins them with `OR` (plain `LIKE` on MySQL and SQLite). `fullText` is PostgreSQL only and compiles to `to_tsvector(...) @@ plainto_tsquery(...)`, or `websearch_to_tsquery(...)` with `queryMode: "websearch"`. `language` must be a plain identifier, optionally schema qualified; anything else is a 400.

## Filter, sort, cursor and upsert types

Added in 3.4.0. See [Filtering](/docs/filtering), [Pagination and sorting](/docs/pagination-sorting), [Cursor pagination](/docs/cursor-pagination) and [Upsert](/docs/upsert).

```ts title="query.interface.ts"
type FilterScalar = string | number | boolean | bigint | Date;
type ColumnFilter = FilterScalar | FilterScalar[] | FilterOperators | null | undefined;

interface FilterOperators {
  eq?: unknown; neq?: unknown; gt?: unknown; gte?: unknown; lt?: unknown; lte?: unknown;
  like?: string; ilike?: string;
  in?: unknown[]; notIn?: unknown[]; between?: [unknown, unknown];
  isNull?: boolean | "true" | "false"; isNotNull?: boolean | "true" | "false";
  startsWith?: string; endsWith?: string; contains?: string;
  iStartsWith?: string; iEndsWith?: string; iContains?: string;
  arrayContains?: unknown[]; arrayOverlaps?: unknown[]; jsonContains?: unknown;
}
type FilterOperator = keyof FilterOperators;

interface FilterGroup { and?: CrudFilter[]; or?: CrudFilter[]; not?: CrudFilter }
type CrudFilter = FilterGroup & {
  [key: string]: ColumnFilter | CrudFilter | CrudFilter[] | CollectionFilter;
};

type SortOrder = "asc" | "desc";
interface SortColumn { column: string; order?: SortOrder } // order defaults to "asc"
type SortInput = string | Array<string | SortColumn>;

interface CursorPaginationOptions {
  cursor?: string | null;
  after?: string | null; // alias of cursor
  limit?: number;
  sortBy?: SortInput;
  sortOrder?: SortOrder;
  count?: boolean;       // default false
}
interface CursorPage<T> { data: T[]; limit: number; nextCursor: string | null; total?: number }

interface UpsertOptions { conflictTarget?: string | string[]; update?: string[] }
type BulkMode = "set" | "perItem";
```

`CrudAllowlists` is the seven allowlist keys of `SqlCrudConfig`, from `filterableColumns` to `writableColumns`. `ParseCrudQueryOptions` extends it with `relations`, `primaryKey`, `searchColumns`, `allowTrash` and `ignore`; it and `ParsedCrudQuery` are described on [Parse query strings into filters](/docs/query-parsing).

## Page, count, scope, event and controller types

Added in 3.5.0. See [Relation filters](/docs/relation-filters), [Aggregates](/docs/aggregates), [Multi-tenancy](/docs/multi-tenancy), [Global hooks and write events](/docs/events), [CRUD controller factory](/docs/controller-factory) and [OpenAPI docs](/docs/openapi).

interface CollectionFilter { some?: CrudFilter; none?: CrudFilter; every?: CrudFilter }

type CrudContextValue = Record<string, unknown>;
type CrudScopeValues = Record<string, unknown>;
type CrudScope = CrudScopeValues | ((context: CrudContextValue) => CrudScopeValues | null);

type CrudWriteOperation = "create" | "update" | "upsert" | "softDelete" | "restore"
  | "delete" | "attach" | "detach" | "sync";
type CrudEventPhase = "before" | "after";
interface CrudEvent<T = any> {
  entity: string; operation: CrudWriteOperation; phase: CrudEventPhase; bulk: boolean;
  ids: unknown[]; input?: unknown; rows: T[]; transaction?: unknown; context?: CrudContextValue;

interface CrudSubscriber<T = any> {
  entities?: string[];
  beforeWrite?(e: CrudEvent<T>): void | Promise<void>;
  afterWrite?(e: CrudEvent<T>): void | Promise<void>;

type CrudRouteName = "list" | "trash" | "get" | "create" | "update" | "delete"

interface CrudRouteOptions { enabled?: boolean; decorators?: MethodDecorator[] }
interface CrudControllerOptions {
  path?: string;
  idType?: "int" | "uuid" | "string";
  dto?: { create?: Type<unknown>; update?: Type<unknown> };
  query?: ParseCrudQueryOptions;
  routes?: Partial<Record<CrudRouteName, boolean | CrudRouteOptions>>;
  decorators?: MethodDecorator[];

## Service interface types

`ICrudService<T, CreateDto, UpdateDto, FilterDto>` is the interface `SqlBaseCrudService` implements: `find`, `findOne`, `findAll`, `create`, `update`, `softDelete`, `restore`, `delete`, the five mass methods, `exists` and `count`. It types options as `OperationOptions`, the older subset of `SqlOperationOptions` (`transaction`, `relations`, `select`, `search`, `hooks`).

```ts title="crud-service.interface.ts"
interface BulkOperationResult<T> {
  success: boolean;
  data?: T[];
  errors?: Array<{ id?: any; index?: number; error: Error }>;
}

type SqlDialect = "postgresql" | "mysql" | "sqlite";
type PrimaryKeyType = "serial" | "bigserial" | "int" | "bigint" | "uuid"; // deprecated setting
```

## Common questions

<Accordions>
  <Accordion title="Is schema required when I pass a connectionString?">
    No. `schema` is optional. When you give it, the module passes it to `drizzle()` as it builds the PostgreSQL or MySQL connection.
  </Accordion>
  <Accordion title="Do allowlist arrays merge across the config layers?">
    No. Only `softDelete`, `timestamps`, `pagination` and `sql` merge one level deep. An array set in `forFeature` replaces the one from `@CrudService`.
  </Accordion>
  <Accordion title="What happens if I set useReturning to true on MySQL?">
    The service turns it off when it is built and logs a warning, because MySQL has no `RETURNING`. Written rows are read back with a `SELECT` instead.
  </Accordion>
  <Accordion title="What is the default sort of findAll?">
    With no `sortBy` and no `defaultSort`, rows are ordered by the primary key, ascending. Set `defaultSort` per entity, or `defaults.sortOrder` in `forRoot` to sort by the `createdAt` column.
  </Accordion>
</Accordions>
