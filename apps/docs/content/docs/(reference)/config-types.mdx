The package exposes two config types: `DrizzleCrudConfig` (the input to `forRoot` / `forRootAsync`) and `SqlCrudConfig` (the merged, per-entity config the base class actually uses).

## `DrizzleCrudConfig`

The input to `DrizzleCrudModule.forRoot(config)` and `forRootAsync`. It describes the project-level configuration: the database connection, schema, and global defaults.

```ts twoslash
// ---cut---
interface DrizzleCrudConfig {
  /** Required. */
  dialect: 'postgresql' | 'mysql';

  /** PostgreSQL: connection string. The module builds the connection. */
  connectionString?: string;

  /** Any dialect: pre-built Drizzle instance. Required for MySQL. */
  db?: any;

  /** Required when building from connectionString. */
  schema?: Record<string, unknown>;

  /** Per-project defaults applied to every entity unless overridden. */
  defaults?: {
    softDelete?: boolean;
    timestamps?: boolean;
    /** Either key alone keeps the other's default. */
    pagination?: { defaultLimit?: number; maxLimit?: number };
    sortOrder?: 'asc' | 'desc';
  };

  /** Dialect tuning. */
  sql?: {
    caseSensitive?: boolean;
    useReturning?: boolean;
    /** @deprecated Has no effect. */
    jsonSupport?: boolean;
    /** @deprecated Has no effect. */
    enableFullTextSearch?: boolean;
  };

  /** @deprecated Has no effect: there are no global hooks. */
  hooks?: { enableGlobalHooks?: boolean };
}
```

### Defaults

```ts
defaults: {
  softDelete: true,
  timestamps: true,
  pagination: { defaultLimit: 20, maxLimit: 100 },
  // sortOrder: opt-in (no fallback)
}

sql: {
  caseSensitive: false,
  useReturning: dialect === 'postgresql',
}
```

`sql.jsonSupport`, `sql.enableFullTextSearch`, `hooks.enableGlobalHooks` and `primaryKeyType` are deprecated. Nothing reads them, so they have no effect. They are still accepted so existing configs compile, and will be removed in the next major version.

## `SqlCrudConfig`

The fully-resolved, per-entity configuration. The package constructs this by layering:

```
global defaults (DrizzleCrudConfig)
  → @CrudService decorator metadata
    → forFeature { config }
      → db, table (set by forFeature)
```

`softDelete`, `timestamps`, `pagination` and `sql` merge one level deep at every layer, so each layer only names the settings it changes. Any other key replaces the value from the layer before. When the service is built it checks that the `softDelete.column` and `timestamps` keys exist on the table, and throws with the key to use if one does not.

```ts twoslash
type RelationConfig = { table: any };
// ---cut---
interface SqlCrudConfig {
  // ---- Set by the module ----
  dialect: 'postgresql' | 'mysql';
  db: any;
  table: any;

  // ---- Primary key ----
  primaryKey: string;              // default 'id'
  /** @deprecated Has no effect: the type comes from the column. */
  primaryKeyType?:
    | 'serial' | 'bigserial' | 'int' | 'bigint' | 'uuid';

  // ---- Soft delete ----
  softDelete?: {
    enabled: boolean;
    column: string;               // the table key, e.g. 'deleted_at' or 'deletedAt'
  };

  // ---- Timestamps ----
  timestamps?: {
    createdAt: string;            // the table key, e.g. 'created_at'
    updatedAt: string;            // the table key, e.g. 'updated_at'
  };

  // ---- Pagination ----
  pagination?: {
    defaultLimit: number;
    maxLimit: number;
  };

  // ---- Default ORDER BY ----
  defaultSort?: Array<{
    column: string;
    order: 'asc' | 'desc';
  }>;

  // ---- Dialect tuning ----
  sql?: {
    caseSensitive: boolean;
    useReturning: boolean;
    /** @deprecated Has no effect. */
    jsonSupport: boolean;
    /** @deprecated Has no effect. */
    enableFullTextSearch: boolean;
  };

  // ---- Relations: belongs-to, has-many, many-to-many, nested ----
  relations?: Record<string, RelationConfig>;

  // ---- Allowlists (CrudAllowlists). Unset allows everything. ----
  filterableColumns?: string[];   // columns and 'relation.column'
  sortableColumns?: string[];     // columns and 'belongsTo.column'
  selectableColumns?: string[];   // columns and dotted paths
  searchableColumns?: string[];
  loadableRelations?: string[];   // relation paths
  writableColumns?: string[];     // create, update, upsert
}
```

The allowlists are described in [Allowlists](/docs/allowlists). Arrays replace, they do not merge, across the config layers.

## `RelationConfig`, `RelationsConfig` and `RelationType`

```ts twoslash
type SortColumn = { column: string; order: 'asc' | 'desc' };
// ---cut---
type RelationType = 'belongsTo' | 'hasMany' | 'manyToMany';

interface RelationConfig {
  table: any;                  // the target Drizzle table
  type?: RelationType;         // defaults to 'belongsTo'
  // belongs-to
  localKey?: string;           // the FK column on the *current* table (required)
  references?: string;         // the target column (defaults to 'id')
  // has-many
  foreignKey?: string;         // the column on the *target* table pointing back here (required)
  parentKey?: string;          // the column on the current table it matches (defaults to that table's primary key)
  // many-to-many
  through?: any;               // the join table (required)
  throughLocalKey?: string;    // join column matching parentKey (required)
  throughForeignKey?: string;  // join column matching references (required)
  // collections only
  orderBy?: SortColumn[];      // how to order the children, applied in SQL
  // relations of the RELATED table, addressable as 'relName.childName'
  relations?: Record<string, RelationConfig>;
}

type RelationsConfig = Record<string, RelationConfig>;
```

A relation missing its required keys throws when the service is constructed, nested relations included, with the full path in the message. See [Relations](/docs/relations).

## `RelationNode` and `SelectTree`

The resolved eager-loading plan and the parsed `options.select`. Both are exported for subclasses that override the loader; normal use never touches them.

```ts twoslash
type RelationConfig = { table: any };
// ---cut---
interface RelationNode {
  name: string;
  config: RelationConfig;
  children: RelationNode[];
  joined?: boolean;   // folded into the main query as a LEFT JOIN
}

interface SelectTree {
  base: string[];
  relations: Record<string, SelectTree>;
}
```

## `SqlSearchOptions`

`SqlOperationOptions.search` is accepted by `findAll` and `count`.

```ts twoslash
// ---cut---
type SqlSearchMode = 'ilike' | 'fullText';

interface SqlSearchOptions {
  term: string;
  columns: string[];
  mode?: SqlSearchMode;
}
```

The default mode is `ilike`, which searches each configured column with a
contains-style pattern and joins the column predicates with `OR`. `fullText` is
PostgreSQL-only and compiles to `to_tsvector(...) @@ plainto_tsquery(...)`.

## Filter, sort, cursor and upsert types

Added in 3.4.0. See [Filtering](/docs/filtering), [Pagination & sorting](/docs/pagination-sorting), [Cursor pagination](/docs/cursor-pagination) and [Upsert](/docs/upsert).

```ts
type FilterScalar = string | number | boolean | bigint | Date;
type ColumnFilter = FilterScalar | FilterScalar[] | FilterOperators | null | undefined;

interface FilterOperators {
  eq?; neq?; gt?; gte?; lt?; lte?;
  like?: string; ilike?: string;
  in?: unknown[]; notIn?: unknown[]; between?: [unknown, unknown];
  isNull?: boolean | 'true' | 'false'; isNotNull?: boolean | 'true' | 'false';
  startsWith?: string; endsWith?: string; contains?: string;
  iStartsWith?: string; iEndsWith?: string; iContains?: string;
  arrayContains?: unknown[]; arrayOverlaps?: unknown[]; jsonContains?: unknown;
}
type FilterOperator = keyof FilterOperators;

interface FilterGroup { and?: CrudFilter[]; or?: CrudFilter[]; not?: CrudFilter }
type CrudFilter = FilterGroup & { [key: string]: ColumnFilter | CrudFilter | CrudFilter[] };

type SortInput = string | Array<string | SortColumn>;

interface CursorPaginationOptions {
  cursor?: string | null;
  after?: string | null;   // alias of cursor
  limit?: number;
  sortBy?: SortInput;
  sortOrder?: 'asc' | 'desc';
  count?: boolean;         // default false
}
interface CursorPage<T> { data: T[]; limit: number; nextCursor: string | null; total?: number }

interface UpsertOptions { conflictTarget?: string | string[]; update?: string[] }
type BulkMode = 'set' | 'perItem';
```

`ParseCrudQueryOptions` and `ParsedCrudQuery` are on [Parse query strings into filters](/docs/query-parsing#what-does-it-return).

## `CrudFeature`

The input to `forFeature`:

```ts twoslash
import { SqlBaseCrudService, type SqlCrudConfig } from 'nestjs-drizzle-crud';
// ---cut---
type CrudFeatureConfig = Partial<
  Omit<SqlCrudConfig, 'softDelete' | 'timestamps' | 'pagination' | 'sql'>
> & {
  softDelete?: Partial<NonNullable<SqlCrudConfig['softDelete']>>;
  timestamps?: Partial<NonNullable<SqlCrudConfig['timestamps']>>;
  pagination?: Partial<NonNullable<SqlCrudConfig['pagination']>>;
  sql?: Partial<NonNullable<SqlCrudConfig['sql']>>;
};

interface CrudFeature {
  service: typeof SqlBaseCrudService;
  table: any;                  // Drizzle table
  config?: CrudFeatureConfig;  // per-entity overrides
}
```

`CrudFeatureConfig` is exported. Every key is optional, `db`, `table` and `dialect` are set for you, and the four object settings merge with the project defaults. Before 3.3.1 `config` was typed `Record<string, any>`, so a typo or a half-filled `pagination` compiled.
