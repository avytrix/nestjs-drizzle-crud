description: "parseCrudQuery and service.parseQuery turn ?age[gte]=18&status=active&sortBy=-name&page=2 into typed filters, pagination and options, coerced by Drizzle column type."
---

`service.parseQuery(query)` turns an HTTP query string into the three arguments `findAll` takes, so a list endpoint is one line of controller code. Values are coerced by the Drizzle column type, and anything the table does not have is a 400.

```ts accent=nest title="countries.controller.ts"
@Get()
findAll(@Query() query: Record<string, unknown>) {
  const q = this.countries.parseQuery(query);
  return q.isCursor
    ? this.countries.findByCursor(q.filters, q.pagination, q.options)
    : this.countries.findAll(q.filters, q.pagination, q.options);
}
```

`parseQuery` reads the entity's own table, relations, primary key and [allowlists](/docs/allowlists). The standalone `parseCrudQuery(query, table, options)` does the same for code that has no service at hand.

## What does the query string look like?

Each filter is a key: a bare value for an exact match, or brackets for an operator. A relation name filters by a related column.

```txt
GET /countries?status=active                 exact match
GET /countries?population[gte]=1000000       operator
GET /countries?region_id[in]=1,3             list operand, comma separated
GET /countries?code=IN&code=NP               repeated key: IN (...)
GET /countries?region[name]=Asia             belongs-to column (region.name=Asia works too)
GET /countries?states[name]=Kerala           has-many or many-to-many column
GET /cities?state[country][code]=IN          a path through relations (state.country.code=IN too)
GET /countries?states[none][name]=Kerala     some / none / every on a collection
GET /countries?states[some]=                 has at least one state
GET /countries?or[0][code]=IN&or[1][code]=NP OR group
GET /countries?not[region][name]=Asia        NOT group
GET /countries?sortBy=region.name,-name&page=2&limit=20
GET /countries?fields=id,name,region.name&with=region
GET /countries?search=nep
GET /countries?cursor=                       first keyset page
GET /countries?withCount=false               skip the COUNT(*)
GET /countries?counts=states,tags            _count on each row
```

A relation filter can go on through the related table's own relations, and a collection takes `some`, `none` or `every` as the next key; `filterableColumns` is checked against the full dotted path (`state.country.code`). See [Relation filters](/docs/relation-filters).

Every [filter operator](/docs/filtering#operator-reference) works in brackets. `in`, `notIn`, `between`, `arrayContains` and `arrayOverlaps` take a comma separated list; use a repeated key (`name[in]=a&name[in]=b`) when a value contains a comma. `jsonContains` takes JSON: `meta[jsonContains]={"size":"L"}`.

The parser reads both Express 5's default flat keys (`age[gte]`) and the nested objects of the `qs` parser (`app.set('query parser', 'extended')`), so it works whichever one your app uses.

## Which parameters are not filters?

| Parameter | Becomes | Notes |
| --- | --- | --- |
| `page`, `limit` | `pagination.page`, `pagination.limit` | Positive integers, otherwise a 400. `limit` is still capped at `maxLimit`. |
| `sortBy` | `pagination.sortBy` | Comma list. `-name` sorts descending, `name` ascending, `region.name` sorts by a belongs-to column. |
| `sortOrder` | direction of the unprefixed `sortBy` entries | `asc` or `desc`. |
| `fields` | `options.select` | Comma list, dotted paths for relations. |
| `with` | `options.relations` | Comma list of relation paths. |
| `search` | `options.search` | Searches `searchColumns`, or the entity's `searchableColumns`. Without either it is a 400. |
| `cursor` / `after` | `pagination.cursor` | Sets `isCursor`. Empty means the first page. See [Cursor pagination](/docs/cursor-pagination). |
| `count` | `pagination.count` | `true` asks `findByCursor` for a total. |
| `withCount` | `pagination.withCount` | `false` makes `findAll` skip the count: `total` is `null` and `hasMore` is set. See [Pagination](/docs/pagination-sorting#how-do-i-skip-the-count-query). |
| `counts` | `options.counts` | Comma list of has-many or many-to-many relations to count under `_count`. Checked against `loadableRelations`; a belongs-to is a 400. See [Aggregates](/docs/aggregates). |
| `withDeleted`, `onlyDeleted` | `options.withDeleted`, `options.onlyDeleted` | Only with `allowTrash: true`; otherwise they are unknown filter columns, so a 400. See [Soft delete](/docs/soft-delete). |

Every other key is a filter. To read a parameter of your own, list it in `ignore` and take it from the query yourself.

## How are values coerced?

By the Drizzle column, so the service gets the type it expects:

| Column | Query value | Result |
| --- | --- | --- |
| integer, serial, real, double, `numeric` in number mode | `"18"` | `18`. Not a number: 400. |
| `bigint` in bigint mode | `"9007199254740993"` | `9007199254740993n`, exact. |
| `numeric` / `decimal` in string mode | `"10.50"` | Checked as a number, kept as the exact string. |
| boolean | `"true"`, `"false"`, `"1"`, `"0"` | `true` / `false`. Anything else: 400. |
| timestamp, date (date mode) | `"2025-01-01"` | A `Date`. Not a date: 400. |
| text, varchar, uuid, enum | `"Asia"` | Left as a string. Postgres checks uuid and enum values, and a bad one is a 400. |
| array operands | `"red,blue"` | Each element coerced by the array's element type. |

## What is a 400?

The same things the service rejects, caught before any SQL runs: an unknown column, relation, operator, sort column, `fields` entry or `with` path; a value the column cannot hold; a malformed key such as `a[b`; a key given twice where one value is expected (`page=1&page=2`); and anything outside an [allowlist](/docs/allowlists). Keys such as `__proto__` are refused outright.

## Options

```ts
const q = this.tags.parseQuery(query, {
  allowTrash: true,            // accept withDeleted / onlyDeleted
  searchColumns: ['name'],     // what ?search= looks in
  ignore: ['format'],          // a parameter the controller reads itself
});
```

`parseCrudQuery(query, table, options)` also takes `relations`, `primaryKey` and the allowlist keys, which `parseQuery` fills in from the entity config.

## What does it return?

```ts
interface ParsedCrudQuery {
  filters: CrudFilter;
  pagination: { page?; limit?; sortBy?: SortColumn[]; cursor?: string | null; count?; withCount? };
  sort: SortColumn[];
  select?: string[];
  relations?: string[];
  counts?: string[];
  search?: SqlSearchOptions;
  options: SqlOperationOptions;   // select, relations, counts, search, withDeleted, onlyDeleted
  isCursor: boolean;
}
```

Type the service's fourth generic as `CrudFilter` so the parsed filters fit without a cast:

```ts
export class CountriesService extends SqlBaseCrudService<
  Country, CreateCountryDto, UpdateCountryDto, CrudFilter
> {}
```
