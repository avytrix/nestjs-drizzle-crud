---
title: OpenAPI (Swagger) docs for list queries
description: "ApiCrudQuery and ApiCrudList document page, limit, sortBy, cursor, withCount, search, fields, with, counts and every filterable column in Swagger, from the entity's allowlists."
---

`@ApiCrudList(source)` documents a list route in Swagger: every query parameter `parseQuery` reads (page, limit, sort, cursor, withCount, search, fields, relations, counts) plus each filterable column with its type, and the page envelope as the 200 response. `@ApiCrudQuery(source)` does the parameters alone.

```ts accent=nest title="countries.controller.ts"
import { ApiCrudList } from 'nestjs-drizzle-crud';
import { countries } from '../db/schema';
import { countriesCrud } from './countries.crud';

@Get()
@ApiCrudList({ table: countries, ...countriesCrud })
findAll(@Query() query: Record<string, unknown>) {
  const q = this.countries.parseQuery(query);
  return this.countries.findAll(q.filters, q.pagination, q.options);
}
```

## Do I need @nestjs/swagger?

Only if you use these decorators. `@nestjs/swagger` is an optional peer dependency: the package requires it the first time one of the decorators runs, so an app without Swagger never loads it and has nothing new to install. Without it installed, applying a decorator throws an error that says so.

```bash
pnpm add @nestjs/swagger
```

## What do I pass as the source?

The same facts the service uses, so the docs match what the API accepts:

- **A config object with the table**: `{ table, relations, filterableColumns, sortableColumns, selectableColumns, searchableColumns, loadableRelations, allowTrash }`. Keep the entity config in one constant and spread it into both `forFeature` and the decorator.
- **A service class decorated with `@CrudService({ table, ... })`**, whose metadata already holds the table and lists. A class without that metadata throws, naming what to pass instead.

Config set only in `forFeature` is not visible when the decorator runs, which is why the shared constant is the usual pattern.

## What gets documented?

| Parameter | Documented when |
| --- | --- |
| `page`, `limit`, `sortBy`, `sortOrder`, `withCount`, `fields` | always; `sortBy` and `fields` list the sortable and selectable columns |
| `with`, `counts` | the entity has relations; `with` lists the loadable ones |
| `search` | `searchableColumns` (or `searchColumns`) is set |
| `cursor`, `count` | unless `{ cursor: false }` |
| `withDeleted`, `onlyDeleted` | `allowTrash: true`, and not on a trash route (`{ trash: true }`) |
| one parameter per filter column | every entry of `filterableColumns`, or every column when it is unset |

A relation path is written the way a query string sends it: `region.name` becomes `region[name]`. Each filter parameter carries the column's OpenAPI type (integer, number, boolean, date-time, uuid, an enum's values) and lists the bracket operators. Every parameter is optional.

`ApiCrudList` adds the 200 response: `{ data, total, page, limit, hasMore, nextCursor }`, with the row schema built from the table's columns and `total` marked nullable for `withCount=false`.

## How do I serve the document?

```ts accent=nest title="main.ts"
import { DocumentBuilder, SwaggerModule } from '@nestjs/swagger';

SwaggerModule.setup('docs', app, () =>
  SwaggerModule.createDocument(
    app,
    new DocumentBuilder().setTitle('My API').setVersion('1.0').build(),
  ),
);
```

The UI is at `/docs` and the JSON at `/docs-json`.

## Does the controller factory document itself?

Yes, with the `openapi` option of [`createCrudController`](/docs/controller-factory). It applies `ApiCrudList` to the list route and `ApiCrudList(source, { trash: true })` to the trash route:

```ts accent=nest
createCrudController(ProjectsService, {
  openapi: { table: projects, ...projectsCrud },
});
```
