`findAll(filters)` and `count(filters)` accept a plain object keyed by column name. `null` and `undefined` values are skipped, so a query DTO with empty fields can go straight in. A key that is not a column or a configured relation is a 400 (`BadRequestException`), the same as an unknown `sortBy`.

## Bare values

```ts
await service.findAll({
  status: 'active',           // string: exact match (case-insensitive on text columns)
  isVerified: true,            // boolean: equality
  organizationId: 42,          // number: equality
  role: ['admin', 'editor'],   // array: IN (...)
  createdAt: new Date('2025-01-01T00:00:00Z'), // Date: equality
});
```

### Can I pass query string values as strings?

Yes. HTTP query values always arrive as strings, and the package handles that per column type:

- **Text columns** (`text`, `varchar`, `char`) compare case-insensitively with `lower(column) = lower(value)` when `sql.caseSensitive` is `false`, the default.
- **Integer, uuid, enum and other non-text columns** compare with a plain `=`, and Postgres casts the string to the column type. `{ author_id: '1' }` matches `author_id = 1`.
- **Date and timestamp columns** turn the string into a `Date` first, so `{ createdAt: { gte: '2025-01-01' } }` works. A string that is not a date is a 400.

A value the column cannot hold, such as `'abc'` for an integer or an enum label that does not exist, is a 400 too, never a raw 500.

<Callout type="warn" title="Strings are exact, not partial">
  A bare string is an **exact** match. On a text column with
  `sql.caseSensitive` set to `false` (the default) the package compiles it to
  `lower(column) = lower(value)`,
  so the match is case-insensitive and `%` / `_` / `\` in the value are
  treated as literal data, never wildcards. For partial / pattern
  matching, use the explicit `ilike` operator with your own `%`
  wildcards:

  ```ts
  await service.findAll({ name: { startsWith: 'jo' } }); // starts with "jo"
  await service.findAll({ name: { contains: 'doe' } });  // contains "doe"
  await service.findAll({ name: { ilike: 'jo%n' } });    // your own pattern
  ```

  `startsWith`, `endsWith` and `contains` escape `%`, `_` and `\` for you,
  so `{ contains: '50%' }` matches the text "50%".
</Callout>

## Operator object

For anything beyond equality, wrap the value in an object with operator keys:

```ts
await service.findAll({
  age: { gte: 18, lt: 65 },       // 18 <= age < 65
  email: { neq: 'system@example.com' },    // not the system account
  name: { ilike: 'jo%' },         // pattern match: you supply the wildcards
  archivedAt: { isNull: true },    // archivedAt IS NULL
  publishedAt: { isNull: false },  // publishedAt IS NOT NULL
  state: { name: 'Karnataka' },    // filter by related column: see Relations
});
```

Multiple operators in the same object are AND-ed together. An operator the package does not know, such as `{ roughly: 2 }`, is a 400 rather than being dropped.

### Operator reference

| Operator | SQL | Notes |
| --- | --- | --- |
| `eq` | `=` | Exact and case-sensitive, even on text columns. |
| `gt` / `gte` / `lt` / `lte` | `>` `>=` `<` `<=` | Numeric and date columns. Date strings are parsed. |
| `neq` | `<>` | Not equal. |
| `like` | `LIKE` | Caller supplies `%` wildcards. |
| `ilike` | `ILIKE` (PostgreSQL) / `LIKE` (MySQL) | Case-insensitive. Caller supplies `%`. MySQL has no `ILIKE`; its default collations already ignore case. |
| `in` | `IN (...)` | The value must be an array, otherwise 400. |
| `notIn` | `NOT IN (...)` | The value must be an array, otherwise 400. |
| `between` | `BETWEEN a AND b` | `[from, to]`, both inclusive. Date strings are parsed. |
| `isNull` | `IS NULL` / `IS NOT NULL` | `true` or `"true"` gives `IS NULL`, `false` or `"false"` gives `IS NOT NULL`. Anything else is a 400. |
| `isNotNull` | `IS NOT NULL` / `IS NULL` | The mirror of `isNull`. |
| `startsWith` / `endsWith` / `contains` | `LIKE 'x%'`, `'%x'`, `'%x%'` | Text columns only. The value is escaped. Case-insensitive unless `sql.caseSensitive` is `true` (`ILIKE` on Postgres, `LIKE` on MySQL). |
| `iStartsWith` / `iEndsWith` / `iContains` | `ILIKE` (PostgreSQL) / `LIKE` (MySQL) | Always case-insensitive, whatever `caseSensitive` says. |
| `arrayContains` | `@>` | PostgreSQL array columns: the column holds every value. `{ tags: { arrayContains: ['a', 'b'] } }`. |
| `arrayOverlaps` | `&&` | PostgreSQL array columns: the column holds at least one value. |
| `jsonContains` | `@> '...'::jsonb` | PostgreSQL `jsonb` columns: `{ meta: { jsonContains: { plan: 'pro' } } }`. |

A pattern operator on a column that is not text, an array operator on a column that is not an array, or a PostgreSQL only operator on MySQL is a 400 that says so.

## Combining filters

```ts
await service.findAll({
  status: 'active',
  role: ['admin', 'editor'],     // status='active' AND role IN (...)
  createdAt: { gte: new Date('2025-01-01') },
});
```

All top-level keys are AND-ed.

## How do I OR two filters?

Put them in an `or` array. `and`, `or` and `not` are group keys; each member is a full filter object, so it can hold columns, relation filters, collection filters and more groups:

```ts
await posts.findAll({
  status: 'published',
  or: [
    { author: { name: 'Ann' } },     // a belongs-to relation
    { views: { gte: 1000 } },
  ],
  not: { tags: { name: 'internal' } }, // a many-to-many: no internal tag
});
// status = 'published'
//   AND (author.name = 'Ann' OR views >= 1000)
//   AND NOT (id IN (SELECT ... tags.name = 'internal'))
```

Groups nest, work inside a relation filter (`{ states: { or: [{ name: 'Kerala' }, { name: 'Assam' }] } }`) and apply to `count` too. An `or` whose member is empty matches every row, so it adds nothing. A table column named `and`, `or` or `not` wins over the group key.

<Callout type="info" title="NOT and a missing parent">
  A belongs-to filter inside `not` compares against a `LEFT JOIN`. A row whose
  parent is missing has `NULL` there, and `NOT (NULL = 'Ann')` is not true, so
  `{ not: { author: { name: 'Ann' } } }` also leaves out rows with no author.
  Add `{ or: [{ not: ... }, { author_id: { isNull: true } }] }` if you want them.
</Callout>

## List search across columns

`findAll` and `count` also accept `options.search` when you need a user-facing
search box to combine with normal filters, pagination, sorting, relation filters,
and a correct `total` count.

```ts
const page = await service.findAll(
  { status: 'active' },
  { page: 1, limit: 20, sortBy: 'name', sortOrder: 'asc' },
  {
    search: {
      term: 'john',
      columns: ['name', 'email'],
    },
  },
);

const total = await service.count(
  { status: 'active' },
  { search: { term: 'john', columns: ['name', 'email'] } },
);
```

By default, search compiles to cross-column `ILIKE '%term%'` checks joined by
`OR` (`LIKE` on MySQL). Empty terms and unknown column names are ignored.

```ts
await service.findAll(
  {},
  { page: 1, limit: 20 },
  { search: { term: 'john', columns: ['name', 'email'], mode: 'ilike' } },
);
```

For PostgreSQL full-text matching inside the `findAll` / `count` path, set
`mode: 'fullText'`:

```ts
await service.findAll(
  { status: 'active' },
  { page: 1, limit: 20 },
  {
    search: {
      term: 'john doe',
      columns: ['name', 'bio'],
      mode: 'fullText',
    },
  },
);
```

Use `fullTextSearch()` directly when ranked full-text results are the primary
operation. Use `findAll(..., ..., { search })` when search needs to compose with
the list endpoint's filters and count query.

## What happens with an unknown filter key?

It is rejected with a 400 (`BadRequestException`, message `Unknown filter column: <key>`). Before 3.3.1 the key was dropped, so a typo such as `{ titel: 'x' }` returned every row. The same rule covers a column inside a relation filter (`{ author: { nmae: 'Bob' } }`) and an unknown operator.

The simplest controller hands the query string to [`parseQuery`](/docs/query-parsing), which splits off pagination, sort and options, coerces the values and rejects unknown keys before any SQL runs:

```ts accent=nest
@Get()
findAll(@Query() query: Record<string, unknown>) {
  const q = this.users.parseQuery(query);
  return this.users.findAll(q.filters, q.pagination, q.options);
}
```

Set [allowlists](/docs/allowlists) so a client can only filter on the columns you mean to expose.

## Combining with pagination & sorting

`findAll` takes three positional arguments: filters, pagination, options. See [Pagination & sorting](/docs/pagination-sorting) for the full shape.

```ts
await service.findAll(
  { status: 'active' },
  { page: 2, limit: 25, sortBy: 'createdAt', sortOrder: 'desc' },
);
```

## Filtering by related columns

When you've [declared a many-to-one relation](/docs/relations), use the relation name as a filter key. The package will join the related table for you. With soft delete on, a soft-deleted parent never matches.

```ts
await service.findAll({
  state: { name: 'Karnataka' },
});
```

Multi-level filtering works through the intermediate FK column:

```ts
// cities where state.country_id = 3: no direct relation to countries required
await service.findAll({
  state: { countryId: 3 },
});
```
