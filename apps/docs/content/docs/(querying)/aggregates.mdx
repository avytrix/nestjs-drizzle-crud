---
title: Aggregates, relation counts and countBy
description: "Add _count to rows with options.counts, one GROUP BY per relation and no N+1, and get grouped counts per column value with countBy(column, filters). Soft delete, scope and allowlists apply."
---

`options.counts` puts the number of related rows on each row under `_count`, with one grouped query per relation for the whole result. `countBy(column, filters)` returns how many rows have each value of a column. Both respect soft delete, the tenant scope and the allowlists.

```ts
const page = await authors.findAll({}, {}, { counts: ['posts'] });
page.data[0]._count; // { posts: 10 }
```

## How are relation counts loaded?

With one `SELECT key, count(*) ... WHERE key IN (...) GROUP BY key` per relation, for every row of the page at once, and the relations run concurrently. A page of 50 authors with `counts: ['posts', 'tags']` is the data query, the count query and two grouped queries, never one per row. A has-many counts the related rows; a many-to-many counts the links whose target row is live.

`counts` works on `find`, `findOne`, `findAll`, `findByCursor`, and on the rows a [write returns](/docs/relations-on-writes). When `select` narrows the columns, the key the count groups on is added back.

## Can I count only some related rows?

Pass an object instead of a list. Each value is a filter on the related table, or `true` for all of them:

```ts
await authors.findAll({}, {}, {
  counts: { posts: { status: 'published' }, tags: true },
});
// _count: { posts: 5, tags: 2 }
```

The filter accepts everything a [filter](/docs/filtering) does, groups included.

## What can be counted?

- Only has-many and many-to-many relations. Counting a belongs-to, or a relation that is not configured, is a 400.
- Soft-deleted related rows are not counted.
- The relation must be allowed by [`loadableRelations`](/docs/allowlists) when that list is set.
- Counts are top level: `posts`, not `posts.comments`.

From a query string, `?counts=posts,tags` sets `options.counts`. See [Parse query strings](/docs/query-parsing).

## How do I count rows per column value?

`countBy(column, filters?, options?)` returns one entry per value, largest group first, ties ordered by value:

```ts
await posts.countBy('status');
// [{ value: 'published', count: 15 }, { value: 'draft', count: 14 }]

await posts.countBy('author.name', { status: 'published' });
// [{ value: 'Ann', count: 5 }, { value: 'Bob', count: 5 }, { value: 'Cy', count: 5 }]
```

It is one `GROUP BY` query. The column is a column of the table, or of a top-level belongs-to written as `relation.column`. Filters, `options.search`, the [tenant scope](/docs/multi-tenancy) and soft delete apply as they do in `count`, so soft-deleted rows are not counted unless you pass `withDeleted`. The column must be in [`filterableColumns`](/docs/allowlists) when that list is set, since grouping exposes its values the way filtering does. An unknown column is a 400. The type of `value` is a generic: `countBy<string>('status')`.
