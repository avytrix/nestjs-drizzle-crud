---
title: Relation filters, paths and some, none, every
description: "Filter through relations at any depth (state.country.code) and quantify collections with some, none and every. Compiled to EXISTS and NOT EXISTS subqueries, so rows are never multiplied."
---

A relation filter can go on through the related table's own relations, to any depth, and a filter on a collection can say `some`, `none` or `every`. Everything below the first belongs-to join compiles to an `EXISTS` or `NOT EXISTS` subquery, so parent rows are never multiplied and `total` stays right.

```ts
// Cities in India: city -> state -> country
await cities.findAll({ state: { country: { code: 'IN' } } });

// Authors with no draft posts
await authors.findAll({ posts: { none: { status: 'draft' } } });
```

## How do I filter through more than one relation?

Nest the relation names, as declared in each relation's own `relations` config:

```ts accent=nest
relations: {
  state: {
    table: states,
    localKey: 'state_id',
    relations: {
      country: { table: countries, localKey: 'country_id' },
    },
  },
}
```

```ts
await cities.findAll({ state: { country: { code: 'IN' } } });
await cities.count({ state: { name: 'Kerala', country: { code: 'IN' } } });
```

The top-level belongs-to (`state`) is joined as before. Each deeper level is a correlated `EXISTS`:

```sql
select ... from cities
left join states on cities.state_id = states.id
where exists (
  select 1 from countries crud_sq1
  where crud_sq1.id = states.country_id and lower(crud_sq1.code) = lower($1)
)
```

Each subquery gets its own table alias, so a relation back to a table already in the query (a self relation) still resolves. Soft-deleted related rows never match.

## How do I use some, none and every?

On a has-many or many-to-many relation, the value is a filter (meaning `some`) or an object of quantifiers:

| Filter | Keeps parents that | SQL |
| --- | --- | --- |
| `{ posts: { status: 'draft' } }` | have at least one matching row | `id IN (SELECT ...)` |
| `{ posts: { some: { status: 'draft' } } }` | the same | `id IN (SELECT ...)` |
| `{ posts: { some: {} } }` | have any row at all | `id IN (SELECT ...)` |
| `{ posts: { none: { status: 'draft' } } }` | have no matching row | `NOT EXISTS (...)` |
| `{ posts: { none: {} } }` | have no rows at all | `NOT EXISTS (...)` |
| `{ posts: { every: { status: 'published' } } }` | have no row that fails the filter | `NOT EXISTS (... AND NOT coalesce(filter, false))` |

Several quantifiers in one object are ANDed: `{ posts: { some: { status: 'draft' }, none: { views: 0 } } }`.

## What does every mean for a parent with no rows?

It matches. `every` means "no related row fails the filter", which is true when there are none, as in Prisma. Add `some: {}` when you need at least one: `{ posts: { some: {}, every: { status: 'published' } } }`. A row whose filter evaluates to NULL (a NULL column, say) counts as failing. Soft-deleted related rows are ignored by all three.

## Do they work in groups and counts?

Yes. A relation filter, at any depth and with any quantifier, can sit inside `and`, `or` and `not`, and `count` and `findByCursor` use the same compiler:

```ts
await authors.count({
  or: [{ posts: { every: { status: 'published' } } }, { name: 'Cy' }],
});
await cities.count({ not: { state: { country: { code: 'IN' } } } });
await cities.count({ state: { cities: { some: { name: 'Mysuru' } } } }); // a collection under a belongs-to
```

## How do I send them in a query string?

Brackets or dots, as with one level:

```txt
GET /cities?state[country][code]=IN
GET /cities?state.country.code=IN
GET /authors?posts[none][status]=draft
GET /authors?posts[every][views][gte]=10
GET /authors?posts[some]=
```

`posts[some]=` with no column means "has at least one". See [Parse query strings](/docs/query-parsing).

## How do allowlists treat a path?

`filterableColumns` names the full dotted path to the column: `'state.country.code'` allows the city filter above and nothing else on `country`. Quantifiers do not appear in the path, so `'posts.status'` allows `posts[none][status]` as well as `posts[status]`.
